# Demo Mode

**Purpose:** Define how the platform runs in a sandbox / demo configuration, isolated from production data, suitable for sales demos, training, partner integrations, and internal evaluations.

**Status:** Phase 27 Workstream I deliverable
**Owner:** Platform Engineering + Product

---

## 1. Goals & Non-Goals

### 1.1 Goals

- Run the **entire platform** end-to-end without any production data
- Be indistinguishable from production in UX, calculation behaviour, and reasoning quality
- Reset cleanly to a known state
- Run on a developer laptop or a sandbox tenant in the production environment
- Demonstrate Basel III, IFRS 9, ALM, and conversational analytics convincingly

### 1.2 Non-Goals

- Stress testing or performance benchmarking — those belong to load test environments
- Storing real customer data, even tokenised
- Filing real regulatory returns (demo outputs are watermarked as such)

---

## 2. Modes of Operation

The platform supports four operating modes, configured per tenant:

| Mode | Data | LLM | Outputs |
|---|---|---|---|
| **Production** | Real customer data | Production model, full audit | Real returns, filed |
| **Staging** | Production data clone (PII tokenised) | Production model | Returns generated, not filed |
| **Demo** | Synthetic dataset | Production model | Watermarked outputs |
| **Local Dev** | Tiny synthetic dataset | Production model or mock | Anything |

Demo mode is the focus of this document.

---

## 3. The Synthetic Dataset

### 3.1 Design Principles

The demo dataset must be:

- **Realistic in shape:** distributions of exposures, ratings, currencies, maturities resemble a mid-size bank
- **Self-consistent:** the balance sheet balances; capital ratios are within plausible ranges; LCR/NSFR pass with realistic headroom
- **Diverse enough to be interesting:** edge cases that exercise rules (stage 2/3 ECL, currency mismatch, large exposures)
- **Fixed and versioned:** the exact same dataset every run, reproducible, hash-pinned
- **PII-free:** all counterparty names are clearly fictional ("Sequoia Logistics Ltd.", "Banyan Industries Pvt Ltd"), no resemblance to real entities

### 3.2 Composition

The demo bank, **"Banyan Bank Demo"**, has the following profile:

| Metric | Value |
|---|---|
| Total assets | ₹ 1,20,000 crore (~$14B equivalent) |
| Loan book | ₹ 78,000 crore |
| Investment book | ₹ 25,000 crore |
| Deposits | ₹ 95,000 crore |
| CET1 ratio | ~14.2% |
| LCR | ~128% |
| NSFR | ~112% |
| Loan portfolios | 6 (retail, SME, large corporate, agri, housing, treasury) |
| Counterparties | ~12,000 |
| Positions | ~85,000 |
| Currencies | INR (primary), USD, EUR, GBP |
| Reporting jurisdictions | IN (RBI), US (Fed — for the US branch sub-tenant) |

### 3.3 Generation

Generated by `tools/demo/generate_dataset.py`. The script:

- Seeds with a fixed random seed (deterministic output)
- Builds counterparties from a curated list of fictional names + procedurally generated industry/geography
- Builds positions via a calibrated distribution per portfolio
- Adds intentional "story" cases:
  - One stage-3 corporate exposure that drives a visible ECL movement
  - One currency mismatch in a retail product that triggers an exception
  - One large exposure at 19.5% of capital (just under the 20% breach line)
  - One deposit concentration that affects LCR run-off
  - Two stress scenarios that produce contrasting outcomes
- Writes outputs to `data/demo/` as parquet + JSON
- Records a manifest hash so the dataset version is auditable

### 3.4 Refresh Cadence

The demo dataset is refreshed quarterly, in lock-step with synthetic "reporting dates". A refresh:

- Moves the reporting date forward one quarter
- Applies plausible movements (loan growth, rating migrations, market movements)
- Preserves the "story" cases in modified form so demos can show period-over-period commentary
- Bumps the dataset version

## 4. Demo Reporting Dates

Demo mode operates around a fixed set of "current" dates so screenshots, scripts, and saved dashboards remain stable:

| Demo Date | Purpose |
|---|---|
| **2026-03-31** | Primary "current" demo date (FY end for IN entity) |
| 2025-12-31 | Prior quarter for variance demos |
| 2025-09-30 | Prior quarter for variance demos |
| 2025-03-31 | Year-ago comparison |

When a demo user opens the platform in demo mode, the system clock is logically pinned to **2026-03-31** for filtering, comparisons, and "last quarter" defaults.

## 5. Reasoning Layer in Demo Mode

The reasoning layer (Claude) uses the **production model** in demo mode, with two differences:

1. **Prompts include a demo flag** that allows the model to make light, accurate observations about the fictional bank ("Banyan Bank Demo's CET1 ratio held steady at 14.2% this quarter…") without ever asserting that it represents a real institution.
2. **All reasoning outputs are watermarked** with the line: *"Generated in demo mode. Banyan Bank Demo is a fictional institution; figures are synthetic."*

The reasoning quality must not be degraded — demos are how the platform's reasoning capability is most often evaluated, so degraded output here would misrepresent production quality.

---

## 6. Watermarking

Every visible output in demo mode carries a watermark:

- **UI:** persistent banner at the top: *"DEMO MODE — Synthetic data — Not for filing"*
- **PDF exports:** diagonal watermark across each page reading "DEMO"
- **Excel exports:** header row in each sheet: "DEMO MODE — Synthetic data"
- **API responses:** `X-Demo-Mode: true` header on every response
- **LLM-generated text:** footer line as in §5

The watermark is non-removable through configuration — it is hard-coded based on tenant mode.

## 7. Reset Mechanism

Demo tenants can be reset to the canonical starting state:

### 7.1 Soft Reset

- Restores all user-modifiable state to defaults (saved views, draft workpapers, conversational history)
- Preserves the underlying dataset
- Takes < 30 seconds
- Available via UI to demo admin role
- Useful between successive demos to the same client

### 7.2 Hard Reset

- Restores everything including the dataset to the canonical demo manifest
- Takes < 5 minutes
- Available via admin CLI: `platform demo reset --tenant <id> --confirm`
- Used when the dataset has been intentionally modified for a custom demo and needs to be restored

### 7.3 Cloned Demo Tenants

For customised demos (e.g., a prospect wants the demo tinted to their sector):

- A fresh tenant is cloned from the canonical demo
- Customisations applied (renamed portfolios, adjusted distributions)
- The cloned tenant is non-resetting; it lives until the prospect engagement closes
- All clones expire 90 days after creation unless extended

## 8. Sandbox Isolation

Demo mode is **strictly isolated** from production. No data, no credentials, no network path crosses the boundary.

### 8.1 Isolation Mechanisms

| Layer | Mechanism |
|---|---|
| Database | Separate logical database, separate credentials |
| Object storage | Separate bucket with no IAM overlap |
| Identity | Demo IdP tenant; production users cannot log in to demo without explicit access grant |
| Network | Demo runs in a separate VPC subnet; egress allowlist excludes production endpoints |
| Audit log | Demo audit log writes to a separate sink, never the production audit chain |
| Secrets | Demo uses demo-only secrets, including a demo-only Anthropic API key with billing alerts |
| LLM provider | Same provider, separate API key, separate usage limits |

### 8.2 Prohibited

- Copying production data into demo (even for "realistic" testing)
- Demo tenants writing to any production resource
- Production credentials being used to access demo
- Sharing demo data screenshots with any party that hasn't agreed it is synthetic

## 9. Guided Tours

Three scripted tours ship with demo mode. Each is a sequence of prepared scenes (URL + brief script) that a demo presenter can step through.

### 9.1 Tour 1 — "Quarterly Close" (12 minutes)

- Open ALCO pack for 2026-03-31
- Review balance sheet snapshot
- Drill into LCR: show 128% headline, expand to HQLA composition, show run-off rates
- Show variance commentary auto-generated by reasoning layer
- Drill into a stage-2 ECL movement; show the explanation produced by reasoning
- Sign off as reviewer

### 9.2 Tour 2 — "Regulatory Return Preparation" (15 minutes)

- Open RBI DSB-I template
- Show auto-populated cells from snapshot
- Highlight exception: one cell flagged for review
- Use conversational UI: "Why is this value flagged?"
- Show Claude's explanation referencing the underlying positions
- Resolve exception, re-validate, lock for filing
- Export to regulator format

### 9.3 Tour 3 — "Stress Test Walkthrough" (10 minutes)

- Open stress workbench
- Select two pre-built scenarios ("RBI Severe", "Internal Recession-2Y")
- Run; show capital ratio trajectory under each
- Use conversational UI: "Compare these two scenarios — what's the main difference in capital impact?"
- Show Claude's comparison
- Save scenario set to ALCO pack

### 9.4 Tour Mechanics

- Tours are URLs anchored to specific views with `?tour=t1&step=3` parameters
- The platform shows a discreet, dismissible footer with the tour script
- Tours do not modify state unless the presenter explicitly does so

## 10. Demo Performance

Demos must be snappy. SLAs in demo mode are tighter than production for user-perceived latency:

| Operation | Production p95 | Demo p95 |
|---|---|---|
| Page load | 2s | 1s |
| Conversational response | 8s | 4s |
| Variance narrative | 30s | 8s |
| Drill-down | 1s | 500ms |

Achieved via:

- Pre-warmed caches for canonical demo views
- Pre-computed common conversational queries (with cache invalidation on dataset refresh)
- Lower-latency LLM streaming with prompt prefix caching

---

## 11. Cost Controls

Demo mode is a marketing surface, and LLM costs can spiral if conversational traffic surges. Controls:

- Per-tenant monthly LLM spend cap; alerts at 60%, 80%, 100%
- Conversational rate limit per session
- Response length cap for non-disclosure outputs
- Daily budget reset at midnight tenant-local

---

## 12. Acceptance Criteria

Demo mode is accepted when:

1. A presenter unfamiliar with the codebase can run all three tours end-to-end
2. Soft reset completes in < 30s and hard reset in < 5min on the reference environment
3. Watermarks present on every output
4. No production data accessible from any demo path (verified by isolation test suite)
5. Reasoning quality on a 100-question demo eval is ≥ 90% acceptable
6. Demo tenant deployable via single command: `platform demo provision --name <id>`
7. 30-day cost cap not exceeded under simulated demo traffic load
