## 5. Architecture & Data Flow

```
ExecutiveDashboard (page)
  ├── useQuery: api.snapshots.list({ size: 8 })
  ├── useQuery: api.analytics.lcr(snapshotId, entityId)
  ├── useQuery: api.analytics.nsfr(snapshotId, entityId)
  ├── useQuery: api.analytics.capital(snapshotId, entityId)
  ├── useQuery: /v1/copilot/agent/alerts
  ├── useQueries: api.analytics.lcr × 5 snapshots    (trend)
  ├── useQueries: api.analytics.nsfr × 5 snapshots   (trend)
  └── useQueries: api.analytics.capital × 5 snapshots (trend)
          │
          ▼ Props passed to presentational components:
  ├── BankHealthIndicator   — computed from lcr.passes, nsfr.passes, capital.passes_all
  ├── ExecutiveSAMPanel     — entityName, health, alertCount, snapshotDate
  ├── RegulatoryStatusGrid  — lcr, nsfr, capital (pass-through)
  ├── InsightCard ×4        — derived values from lcr/nsfr/capital (no recalculation)
  ├── RiskHeatmap           — lcr, nsfr, capital (thresholds applied client-side)
  ├── TrendChart ×2         — trendData array built from useQueries results
  ├── ExecutiveDashTimeline — built from snapshots list + alerts
  └── ExecutiveReports      — static list of 7 report types
```

**Invariant preserved:** No financial ratio is computed in the frontend. All values (LCR ratio, NSFR ratio, CET1 ratio, leverage ratio, pass/fail flags) are taken verbatim from engine API responses.

## 6. "Ask SAM" Context Injection Flow

1. User clicks an `AskSAMButton` on any metric
2. Context string stored in `sessionStorage["bsm-copilot-prefill"]`
3. `navigate("/copilot")` fires
4. `CopilotPage` reads `sessionStorage` on mount, pre-fills input, clears key
5. User sees the Copilot with question pre-populated, ready to send

This mechanism is also used by `ExecutiveReports` to pre-fill a report generation request.

## 7. Risk Heatmap Methodology

| Category | Data Source | Green | Amber | Red |
|---|---|---|---|---|
| Liquidity Risk | LCR ratio from engine | ≥ 1.20 | 1.00–1.20 | < 1.00 |
| Capital Risk | CET1 ratio + passes_all | ≥ 8.5% & all pass | Meets min, not all pass | Any capital failure |
| Funding Risk | NSFR ratio from engine | ≥ 1.15 | 1.00–1.15 | < 1.00 |
| Market Risk | Indicative | — | Amber (default) | — |
| Operational Risk | Indicative | — | Amber (default) | — |
| Interest Rate Risk | Leverage ratio (proxy) | ≥ 4.0% | 3.0–4.0% | < 3.0% |

Market and Operational risks require AMA/VaR models not available in the current engine scope and are shown as indicative Amber with explanatory tooltips.

## 8. Theme System

Dark mode is implemented via Tailwind's `darkMode: "class"` strategy. The `ThemeContext` provider:
- Reads initial state from `localStorage["bsm-theme"]`
- Adds/removes the `dark` class on `<html>` element
- Persists preference to `localStorage`
- Exposes `toggleTheme()` consumed by the TopBar Moon/Sun button

All new dashboard components have comprehensive `dark:` variants for every colour and background class.
